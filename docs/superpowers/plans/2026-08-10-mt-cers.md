# MT CERS — Montana campaign finance for local office

> Written after the probe, not before it. `docs/exploration/mt-cers-spike.md` is the evidence this
> plan rests on, and the probe changed the design twice: there is no bulk feed, and CERS publishes
> no meetings.

## Why

OpenFEC covers **federal** candidates. A Gallatin County Commissioner and a Bozeman City
Commissioner have no federal filings at all, so "follow the money" could say nothing about the
officials this project exists to watch. Montana publishes theirs through CERS.

## What the probe settled

| Question | Answer |
|---|---|
| Is it reachable? | **Yes.** No `robots.txt` on the host at all (Tomcat 404, not a `Disallow`), no login, no CAPTCHA, no UA discrimination |
| Is there a structured route? | **Yes** — a server-side DataTables JSON API |
| Is there a *bulk* route? | **No.** No CSV, no export, no documented API. Walked entity by entity |
| Local coverage? | **Yes.** 42 Gallatin County Commissioner candidacies 2000–2026; 342 city candidacies resident in Gallatin |
| Hard line reached? | **No.** No spoofing, TLS manipulation, CAPTCHA solving, session replay or proxy rotation was needed, attempted or built |

## Design decisions, and what each one refuses

**A CERS record is addressed by a request chain, not a URL.** Criteria live in an HTTP session, so
one contribution schedule takes four requests in order. `DocumentRef.metadata` carries the chain and
`fetchDocument` replays it. `ref.url` is the endpoint plus those parameters — a stable, unique,
readable identity that is deliberately *not* dereferenceable.

**CERS publishes no meetings, so the adapter invents none.** The `discover` handler is entirely
meeting-shaped. Rather than manufacture a meeting per filing period so the existing path would
accept a C-5 — a fabricated public record in `meetings`, written to reuse a function —
`SourceAdapter` gained an optional `discoverDocuments`. Its refs are enqueued for `fetch` with no
meeting id and routed in `parse` on the record kind their own adapter stamped. **Nothing sniffs
bytes**: a stored artifact's meaning comes from the ref that asked for it.

**Every query is scoped.** An unbounded contributor search timed out at 60 s during the probe. The
adapter sweeps by county code and campaign type, then one candidate at a time, under an explicit
cap. It never asks CERS an open question.

**Every transaction cites a stored artifact, in a `NOT NULL` column with no cascade.** An unsourced
contribution cannot be inserted, and deleting the bytes under a stored one fails loudly.

**Idempotency is `(artifact_id, row_index)`.** An amendment is different bytes, therefore a
different artifact, therefore its own rows — which is right, because an amendment is a second thing
the filer said, not a correction to the first.

**No donor identity table, and no jurisdiction foreign key.** Resolving "Aas, Barbara" across
filings is an inference; so is "this is a Bozeman candidate", because CERS has no city field
anywhere. `residence_city` holds what was filed; `derived_jurisdiction` holds what we concluded, and
it is NULL.

Three shared-code changes, all additive, two of them bugs the recording found:

- `HttpRequest.redirect` — CERS mints `JSESSIONID` on a **302**, and `fetch` exposes only the final
  response's headers. Following blindly made every search run in a fresh session and return
  `iTotalRecords: 0` **under HTTP 200**. A silent zero from a transparency source is the worst
  available failure.
- `HttpResponse.setCookies` — the flat header map keeps one cookie and CERS sets three.
- `SourceAdapter.discoverDocuments`, `DocumentRef.metadata`, `JurisdictionType` gains `'state'`
  (which migration 037 put in the database and never in the union).

## Deliberately not built

- **No public route and no frontend.** Nothing published, nothing rendered. Storage and provenance
  first; what a reader is shown is a separate change with its own review.
- **No donor-to-vote join.** `cers_ent_id` is stored so it becomes possible; making the claim is not
  this change.
- **No committee sweep.** Committees are reachable and shaped the same way; `cf_filers.filer_type`
  admits them and no code writes one yet, which is visible rather than implied.
- **Contact details are stored, never surfaced.** Candidates' home addresses, personal emails and
  telephone numbers are in the filings. That is a publication decision for an operator.
