## The ladder

Each rung is attempted only when the one above it is genuinely exhausted — and "exhausted" must be
*demonstrated in this file*, not asserted. A rung skipped for convenience is the same failure this
project exists to refuse about the public record.

1. **Build the documented-but-unbuilt.** Every doc, without exception.
2. **Feature parity matrix** against other civic-transparency platforms — research, then document,
   so a future agent finds work here instead of re-deriving it.
3. **Security and test-coverage review** of the public-facing surface.
4. **Design review + UI/UX mockups.**

## Standing rules

Carried from the 0.4.0 and 0.5.0 loops. These are what kept those loops honest.

- **One dev subagent at a time.** No nesting. The main loop plans, verifies, commits, and answers
  the subagent via SendMessage.
- **The subagent never runs a git write command.** No `add`, `commit`, `checkout`, `stash`, `reset`.
  Read-only git is fine. The main loop commits.
- **`git add -A` is banned while an agent is running** — it would sweep the agent's half-finished
  work into a commit that claims to be something else.
- **Verify with real command output.** Never an agent's claim that it passes. `blocked` is not
  `pass`.
- **Never run the backend suite from the main loop while an agent may hold the test DB.**
- **Mutation-verify every guard**, in both directions: it must be *seen* to fail when the thing it
  guards is broken, and seen to pass when it is not.
- **Commit messages go in a file and are passed with `-F`.** Backticks and double quotes inside
  `git commit -m` are shell substitution; two 0.5.0 messages were silently eaten and the commit
  still exited 0.
- **Push to `origin` (Gitea, drives CI) and `github` (mirror, does not).**
- **Anything that changes what is published about a named person, or withdraws live public content,
  stops and goes to the operator.** It gets a spec, not an implementation.

## Model delegation policy

The operator asked for token efficiency. The split:

| Work | Model | Why |
|---|---|---|
| Doc sweeps, inventories, grep-and-report | `sonnet` | Mechanical breadth; no judgement about publication |
| Mechanical implementation against a precise spec | `sonnet` | The spec carries the judgement |
| Verification runs (typecheck/test/build) | main loop, no agent | An agent reporting its own pass is the thing we don't accept |
| Anything touching publication, the review gate, or a person's name | main loop, `opus` | Non-delegable |
| Security review, threat reasoning | `opus` | Getting this wrong is silent |

**The rule under the table:** delegate *breadth*, never *judgement*. A cheaper model reading fifty
files and reporting what it found is a good trade. A cheaper model deciding whether something is
safe to publish is not a trade at all.

## What the survey found

A sonnet sweep of every doc, every plan checkbox, and a TODO/FIXME grep of both source trees. The
grep found **nothing** — no TODO, FIXME, XXX or "not implemented" anywhere in `backend/src` or
`frontend/src`. The only hits were the literal `CW-XXXXXXXX` in a reference-ID docstring and the word
"stub" describing an intentional 8-byte empty-VTT sentinel. **This codebase does not carry its
backlog in comments; it carries it in docs.** Which is why the ladder starts where it does.

Three buckets:

- **A — buildable now, no publication impact.** 10 real items.
- **B — requires an operator decision.** 16 items, of which 12 touch either what is published about a
  named official or a live public surface.
- **C — already built despite a doc saying otherwise.** 8 items, the important discovery below.

### The stale-checkbox hazard (C)

Eight plan files carry unchecked `[ ]` boxes describing work that **shipped weeks ago**: operator
auth (~29 boxes, closed 2026-08-09), full-text search (7 boxes, landed via migration 035),
subscriptions/delivery (27 boxes, all built and shipped dark), tier-A foundations (22 boxes), W0 and
W4 checklists, and three "Tier 6 — reach" items in the 2026-08-14 roadmap (`export/ocd.ts`,
`BotPage.tsx`, `export/receipt.ts`) that all exist in code right now.

This is a live trap, not untidiness. **An unchecked box is an instruction to a future agent**, and the
next loop that reads one of these will rebuild something that already works — against a codebase
where a second implementation of an existing service is precisely how the deleted `agents/` directory
became a second, worse analysis engine writing to the same table. The boxes were never ticked because
nobody goes back; the fix is therefore not to tick them but to mark the file superseded, which is what
the 0.5.0 plan header did when its own premise expired.

### Not for this loop — operator decisions

Recorded so the loop does not quietly reclassify them as buildable. `claim_publication`; the office
gate; enabling `dated_export_archive`; generated finding narrative; the real member roster (blocked —
Bozeman roster 403s from Akamai); `member_id` population (blocked behind the roster); the

`jurisdiction_records_law` population (statute reading, explicitly non-delegable); `rundown_sheets`
revive-or-retire; the W6 funding network layer. Recordings/transcription stays **refused**.

**The reach items deserve a note.** `EVENT_DRAIN_ENABLED`, MCP and prerender are shipped dark over
content that is *already* publication-approved. It is tempting to read that as "so turning them on
changes nothing." It changes the **reach** — a prerendered page is a file on disk that a crawler
indexes, and MCP hands the material to other software. Approved-for-the-site is not the same consent
as approved-for-everywhere, and that difference is the operator's to weigh.
