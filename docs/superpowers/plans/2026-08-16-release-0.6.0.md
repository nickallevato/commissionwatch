## The ladder

Each rung is attempted only when the one above it is genuinely exhausted — and "exhausted" must be
*demonstrated in this file*, not asserted. A rung skipped for convenience is the same failure this
project exists to refuse about the public record.

1. **Build the documented-but-unbuilt.** Every doc, without exception.
2. **Feature parity matrix** against other civic-transparency platforms — research, then document,
   so a future agent finds work here instead of re-deriving it.
3. **Security and test-coverage review** of the public-facing surface.
4. **Design review + UI/UX mockups.**

## Standing rules

Carried from the 0.4.0 and 0.5.0 loops. These are what kept those loops honest.

- **One dev subagent at a time.** No nesting. The main loop plans, verifies, commits, and answers
  the subagent via SendMessage.
- **The subagent never runs a git write command.** No `add`, `commit`, `checkout`, `stash`, `reset`.
  Read-only git is fine. The main loop commits.
- **`git add -A` is banned while an agent is running** — it would sweep the agent's half-finished
  work into a commit that claims to be something else.
- **Verify with real command output.** Never an agent's claim that it passes. `blocked` is not
  `pass`.
- **Never run the backend suite from the main loop while an agent may hold the test DB.**
- **Mutation-verify every guard**, in both directions: it must be *seen* to fail when the thing it
  guards is broken, and seen to pass when it is not.
- **Commit messages go in a file and are passed with `-F`.** Backticks and double quotes inside
  `git commit -m` are shell substitution; two 0.5.0 messages were silently eaten and the commit
  still exited 0.
- **Push to `origin` (Gitea, drives CI) and `github` (mirror, does not).**
- **Anything that changes what is published about a named person, or withdraws live public content,
  stops and goes to the operator.** It gets a spec, not an implementation.

## Model delegation policy

The operator asked for token efficiency. The split:

| Work | Model | Why |
|---|---|---|
| Doc sweeps, inventories, grep-and-report | `sonnet` | Mechanical breadth; no judgement about publication |
| Mechanical implementation against a precise spec | `sonnet` | The spec carries the judgement |
| Verification runs (typecheck/test/build) | main loop, no agent | An agent reporting its own pass is the thing we don't accept |
| Anything touching publication, the review gate, or a person's name | main loop, `opus` | Non-delegable |
| Security review, threat reasoning | `opus` | Getting this wrong is silent |

**The rule under the table:** delegate *breadth*, never *judgement*. A cheaper model reading fifty
files and reporting what it found is a good trade. A cheaper model deciding whether something is
safe to publish is not a trade at all.
